Faces use your browser's built-in Shape Detection API (real on-device AI — best supported on Chrome/Edge). Hands use skin-color segmentation (no model, no download) — it isolates skin-toned blobs, excludes ones overlapping a detected face, then counts finger-like protrusions from the blob's silhouette (a simpler stand-in for convex-hull defect counting). It's lighting- and skin-tone-sensitive and can miscount curled or overlapping fingers — treat the finger count as approximate. Motion uses frame differencing. Objects uses edge/contour detection, then tries a rough guess against 9 categories (cat, dog, car, bottle, cup, chair, plant, phone, book) — a lightweight color+shape matcher trained on ~2–4 real photos per category pulled from a public ImageNet sample set on GitHub, not a neural network. Treat guesses (label + confidence %) as fun, not reliable — it often gets fooled by lighting, background, or angle; anything it doesn't recognize just shows as "Object." Detections render as an AR HUD (bracket reticles, pulsing lock-on dot, floating tag). Pick a face filter to swap the face reticle for a tracked AR overlay (glasses, hat, bunny ears, crown), and use Snapshot to save the current view with all overlays baked in. Hit Snap to disintegrate everything currently detected — hands included — into drifting particles, gauntlet-style — purely a canvas effect, nothing is actually deleted. For full multi-class object recognition, use the Python version instead.
